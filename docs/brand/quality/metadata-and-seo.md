# Metadata and SEO

_Status as of 2026-08-10._

What a crawler, a link preview or a bookmark sees.

## The rule

**A unique title per route**, following one pattern, under about 60 characters.

**A description per route**, 110 to 160 characters, and the canonical one
identical to the manifest and repository descriptions. See
[brand-core](../foundations/brand-core.md).

**A canonical link**, or a recorded reason why one is impossible.

**Open Graph and a social card.** Title, description, image, url, type, site
name, and alt text on the image. Verify with a real fetch - the preview is
generated by someone else's crawler, and reading your own markup does not prove
it worked.

**`robots.txt` states the policy explicitly**, including the private case. A
missing robots file is not a policy.

**Even a private surface needs this.** Titles are what browser history and
bookmarks show. A product where every page is titled the same thing is
unusable from history, regardless of whether a crawler ever sees it.

**Record the routing consequence.** Hash-based routing means everything after
the fragment is invisible to a crawler: no per-route canonical, no per-route
metadata. That is an acceptable trade for a private tool, but it has to be an
accepted trade rather than an unnoticed one.

## What Bothy decided, and why

- **The document title is the product name plus a short qualifier.**
- **The description is the canonical string**, byte-identical to the manifest's.
- **Character set, viewport and language are set.**
- **Both `theme-color` values** are emitted, per scheme.

**The routing consequence is accepted.** The application is hash-routed because
it is served as static files with no server-side rewrite, and it is a private
surface on a personal network. Per-route metadata is therefore not crawlable,
and there is no canonical link. This is recorded rather than fixed.

**Known gaps**, tracked in
[reference/open-questions.md](../reference/open-questions.md): titles are not
per-route - every page shares one title, so browser history is not useful. There
is no `robots.txt`, no Open Graph tags and no social image.

## Dead ends

None recorded.

## How this is verified

- Assert a unique title per route.
- Assert the description string is identical in the page and the manifest.
- Fetch a page as a crawler would and check what comes back.
